## 失败如何被识别

- 注入 `push_error` 后仍返回退出 0 并打印 passed，父执行器判失败。
- 没有明确结果、解析错误、缺失资源、保存错误均不能通过正常案例。
- 无限等待案例到达墙钟期限后，只终止该案例启动的 PID。
- headless 截图返回 unsupported，不能输出假截图或算视觉通过。
- 保存失败案例确认预期错误且无关文件内容保持不变。
- 模板目录已有不同内容时不覆盖；重复相同安装不改变文件；路径越界文件不写入。
- 损坏 PNG 的原生导入退出 **0** 且包含错误日志，仍被正确判断失败。
- JSON 报告引用已处理负例的 `ERROR:` 文本属于数据；日志解析只匹配真实错误记录，同时有回归测试防止漏判实际错误。

负例“通过”表示正确识别预期失败，并不表示故障操作成功。未修复的问题不会通过删除断言、清空项目缓存或降低验收要求隐藏。

## 研究中发现并保留的限制

1. `--editor --script` 探针可访问编辑器单例，但退出有资源泄漏日志。该模式没有作为可靠默认能力；常规脚本使用 SceneTree，导入走原生 `--import`。
2. 一次损坏 SVG 探针使官方 Windows 引擎异常退出。记录保留在 artifacts/failures-1；发布故障集用损坏 PNG 验证稳定的错误判据。该观察不等于所有 SVG 都有问题，也不声称已修复引擎。
3. 沙箱最初限制 Godot 创建 user:// 用户目录，产生启动错误。正式行为测试在允许引擎正常用户数据写入的授权环境执行；没有将这些启动错误忽略后计为通过。
4. LightmapGI.bake 缺少公开绑定，属于默认约束下 unsupported。替代光照只能在满足用户视觉要求后采用。

## 尚未作为实测通过的范围

Linux/macOS、Android/iOS、签名、Web 浏览器、公网/NAT、多种物理后端、AnimationTree 骨骼混合、高级 GPU 特效及性能优化收益都没有列为实测能力。各 Skill 包含相应官方流程和边界，实施具体任务时需要补做验证。

18 个 Skill 各有应触发、非目标和相邻请求，54 条请求已人工核对职责边界；没有把这种评审称为宿主模型选择准确率测试。全局插件尚未安装，实际宿主自动触发需在安装后记录客户端和模型条件。

两份 ZIP 均通过逐文件 SHA256 读回检查；最终包只在候选包测试后更新验证摘要。结构和打包检查由维护工具核验：清单一致、YAML frontmatter、默认提示、共享链接、示例入口、固定版本引用、占位内容和 ZIP 读回。最终结构/搬移记录也写入机器可读结果。复现命令见 [authoring.md](authoring.md)。
